# 下载桥接验收原型

这是独立的、本地使用的 DSH 验收插件，不是正式插件的下载实现。它回答：保持 DSH 的 WebView 下载限制时，网页能否交接一个短期文件票据，由插件 Host 下载并保存 PNG？

## 运行

在仓库根目录运行：

```sh
node --test experiments/download-bridge/probe.test.mjs
node experiments/download-bridge/build.mjs
```

第二条命令输出全新的本地 `.tgz` 路径。通过 DSH 插件管理页安装、启用后，在右侧新标签页选择“下载桥接验收”。点击网页的“导出 PNG 并交给插件”，再点击外壳的“保存 PNG 到本机”。测试只使用公开火焰图标，不读取个人图片。

构建器为每次运行分配唯一预发布版本、随机端口、随机实例及临时能力凭据，生成目录位于 Git 忽略的 `artifacts/download-bridge/<run>/`。安装包不可公开发布。源码不包含运行凭据，也不进入正式 `dsh-image-editor` 包的 `files` 允许列表。验收后关闭标签并卸载此插件，保留本地文件与回执。

## 实际路径

1. DSH Cordis Host 启动仅监听 `127.0.0.1` 的测试服务。
2. 测试网页使用 Canvas 生成 PNG，带自身测试会话上传到 `/exports`。
3. 服务签发绑定单个文件、SHA-256、实例和 60 秒有效期的票据。
4. 网页 `window.open()` 指向专用交接地址，票据放在 fragment。DSH 的 `browser.onOpenRequested` 把事件传给当前 guest 的插件外壳，不打开外部浏览器。
5. 用户点击外壳保存按钮，外壳凭仅其持有的临时能力调用 `/save`。
6. 插件 Host 仅用文件票据下载 PNG，校验哈希，以排他创建方式写入固定验收目录；返回字节数、路径和哈希。

插件未注入网页脚本、未增加 guest preload、未开放 Node 给网页、未解除 `will-download` 限制，文件保存请求不使用网页 Cookie。

## 2026-11-02 实测

宿主：macOS arm64，DSH Desktop `0.2.1-rc.5`；初始验收包 `0.0.1-dev.1`。

- 真实 DSH 中安装、启用、打开测试页、网页生成 PNG、链接事件交接与 Host 保存均通过。
- 生成文件：600 × 360，30,752 字节；SHA-256 为 `0e7752bf1534eec8706497c345f341fd440e88556cc1f472e76a623decc8a7dc`。
- 网页回执、插件回执和本地文件的哈希一致；本地图片已打开检查。
- 同一票据再次交接并保存时，界面显示 `already-saved`，目录中仍只有一个 PNG。
- HTTP 集成测试验证未登录、缺少外壳能力、篡改、过期、并发/重复保存以及文件字节一致性。
- 已检查实际 Cordis 注册/卸载生命周期与客户端 lazy bundle 注册合同。

## 证明范围与正式接入

实测网页和签票服务都是本地测试实现，签票与接收服务由同一个测试进程承载。它证明当前 DSH 的事件交接和插件落盘机制可用，不证明线上神火已经接入，也不替代真实账号、资源归属和跨服务授权验收。本次保存到固定验收目录；系统另存为、下载进度、大文件、取消和错误重试均未实现。`blob:` PSD 未验证。

正式接入仍需三个改动：

1. 神火后端为当前用户可读取的导出结果签发短时文件票据；绑定文档版本、文件和接收插件实例，并提供撤销/重放边界。
2. 线上 `downloadLayerAsset()` 在明确识别到 DSH 嵌入场景时交接票据，普通网页继续原有下载；异步导出完成后的用户触发行为需单独验证。
3. 正式插件接收交接，使用固定神火来源校验和受控保存接口；校验资源、类型、大小、哈希与目标路径，提供取消和结果反馈。优先使用目标 DSH 版本正式提供的 Host 通信接口；本实验的回环 HTTP 通道不能直接照搬为线上生产方案。

本次未修改或部署神火线上前后端，正式编辑器插件继续使用 `0.1.0-dev.4`。生产接入与发布是下一阶段。
